# 🌶️ Spicy Discount Searcher

A Chrome/Brave extension that takes a spreadsheet full of corporate discount
codes, races them against each other on the rental car and hotel sites, and
tells you which one is actually cheapest for your trip.

You give it a pick-up airport and some dates. It opens each vendor's own search
with a different corporate code applied, reads the prices off the results page,
and ranks them.

The last row is the honest caveat. None of these vendors document their search
URLs, so the query parameters in `src/core/deeplinks.ts` are reverse-engineered

a results page, that's the one file to fix — see
[Fixing a deep link](#fixing-a-deep-link).

## Install (Brave or Chrome)

```bash
npm install
npm run build
```

Then load it:

1. Open `brave://extensions` (or `chrome://extensions`).
2. Turn on **Developer mode**.
3. **Load unpacked** → select the `dist/` folder.
4. Pin 🌶️ Spicy Discount Searcher to the toolbar.

Rebuild after any source change and hit **Reload** on the extension card.

## How a search runs

1. You pick a category (cars or hotels), a trip, which vendors to try, and
   which companies' codes to race.
2. The popup expands that into candidates — one per distinct vendor + code
   pair. Codes listed under two companies collapse into one candidate, and an
   Enterprise contract id is also tried at National. Only the first **N** race —
   the **Max codes** box, 12 by default — and that selection is spread across
   both vendors and companies, so it isn't twelve codes from whichever vendor
   sorts first. The plan line names the split it chose.
3. The background service worker opens a **minimised** window and loads two
   candidates at a time by default, each lane pausing 750 ms between its own
   candidates, so your browsing isn't hijacked and no vendor gets hammered.
4. A content script on each page polls until the prices stop changing, then
   reports every offer it found.
5. The tab closes, results stream back into the popup ranked cheapest first,
   with the spread between best and worst. A code that produced no price says
   why — timed out, page had no price, couldn't read the page — and shows what
   the probe actually saw, so "it said no results for Hertz" is answerable
   without reproducing it.

Closing the popup doesn't stop a run — state lives in the service worker and
`chrome.storage.session`, so reopening picks the results back up.

### Comparing fairly

Two guards keep the ranking honest:

- **Price basis and currency.** Every scraped number is tagged `total`,
  `per-day` or `unknown`, and codes are ranked only against others quoting the
  same kind of number in the same currency. A `$29/day` badge cannot undercut a
  rival's real `$210` trip total, and `€99` is not compared with `$120`. Codes
  quoting something else are listed but explicitly not ranked, so they don't
  read as having lost. A daily rate also shows an estimated trip total — clearly
  labelled, and never used for ranking.
- **Class matrix.** If the winning code is only cheap because it surfaced a
  different car class than everyone else, the popup says so instead of
  pretending it won — and says so too when the codes share no class at all,
  which is the weakest evidence there is.
- **Links that missed.** A deep link that lands on a vendor's home page still
  finds a plausible "from $19/day" and would otherwise win. The popup flags a
  result whose page turned out to be the site root.

## The code database

`src/data/codes.generated.json` is **generated** from
`data/source/Hotel & Car Rental Corporate Codes.xlsx`. Don't hand-edit it.

```bash
npm run codes    # needs uv — the script is a PEP 723 uv script
# without uv:  pip install 'openpyxl==3.1.5' && python3 scripts/extract_codes.py
```

The workbook is a human spreadsheet, so the parser has to deal with several
codes per cell (`A541100 or A541105`), Excel turning `260290` into `260290.0`,
booking URLs sitting where a code should be, and parenthetical asides. On the
grid sheets it refuses to read letter-only "codes" out of prose-heavy cells,
which is what stops `Hampton Inn` from becoming a code called `INN`. On the
free-text `Hilton Code` sheet it refuses them outright — every code there
carries a digit, so a letter-only token is the first word of somebody's
employer, not a code.

CI regenerates the JSON and fails if it differs from what's committed, so the
data and the workbook can't drift apart. That check can't tell you the parsing is
_right_, though — change the parser and commit the regenerated output together
and it stays green — so `tests/test_extract_codes.py` covers the decisions: what
counts as a code, what counts as a company, and what is somebody's margin note.
Three codes are filed under `Unattributed` rather than dropped, because the
workbook cell beside them was a qualifier or a note rather than an employer. It
was nine until the `Hilton Code` sheet stopped eating employers' names — see the
known gaps in `CLAUDE.md` for what that recovered.

Swapping the workbook for a live source later means replacing that one script
and keeping the JSON shape — nothing else knows where the codes came from.

## Fixing a deep link

When a vendor's search doesn't pre-fill:

1. Go to the vendor's site and run the search by hand, with the code applied.
2. Copy the URL from the address bar.
3. Update that vendor's builder in `src/core/deeplinks.ts` to match.
4. Flip its `confidence` from `'best-effort'` to `'verified'`. This is visible:
   the popup tells the user when a result came from an unverified link.
5. Update the matching case in `tests/deeplinks.test.ts`.

Price extraction is the same idea in `src/core/extract.ts`: `VENDOR_SELECTORS`
holds per-vendor CSS and a generic currency sweep runs when the selectors miss,
so a vendor redesign degrades instead of breaking. Every vendor has a
`container` selector, which does run and keeps the sweep away from nav and
footer; **none has an `offer` selector**, so the per-offer branch never fires
today. It is tested with an injected config so it works when one is filled in.

## Layout

```
src/
  core/            pure logic, all unit-tested
    types.ts       shared shapes
    vendors.ts     vendor registry — host permissions derive from this
    codes.ts       load/query the database, expand a selection into candidates
    deeplinks.ts   per-vendor search URLs  ← the fragile part
    extract.ts     read prices off a results page
    compare.ts     ranking, savings, class matrix
    messages.ts    popup ↔ background ↔ content protocol
  background/      service worker: queue, tab pool, aggregation
  content/         injected probe, inert unless a run is active
  popup/           UI
  data/            generated code database
public/            manifest.json + icons, copied to dist/ root by vite
tests/             vitest unit tests, plus pytest for the workbook parser
  helpers/         chrome API fake the service-worker suite is built on
data/source/       the workbook everything is generated from
scripts/
  extract_codes.py workbook → JSON
  make_icons.py    generates the PNG icons
  check-dist.mjs   CI guard that dist/ is loadable, and that the content
                   script is still a classic script
```

## Development

Requires Node `^22.22.2 || ^24.15.0 || >=26.0.0`, which is jsdom's own range
copied verbatim — it rules out 23.x, 25.x and Node 24 below 24.15, and every
other dependency permits a superset of it. A test-only dependency therefore
sets the supported runtime for everyone, including anyone who only wants to
build. CI runs 22.

```bash
npm run build        # typecheck + both vite builds
npm test             # vitest
npm run lint         # eslint
npm run format       # prettier
npm run format:check # what CI enforces
```

The workbook parser is Python and tested separately:

```bash
pip install 'openpyxl==3.1.5' 'pytest==8.4.2'
python3 -m pytest tests -q
```

CI runs five jobs on every PR. `main` is protected on four of them — they must
pass and the branch must be up to date before merge. The fifth, `test node NN`,
is the Node version matrix; `test` aggregates it into the single required
context, so adding a version never means editing branch protection:

| Job                        | What it does                                                                      |
| -------------------------- | --------------------------------------------------------------------------------- |
| `build / typecheck / lint` | typecheck, eslint, prettier, both vite builds, `check-dist.mjs`, `npm audit`      |
| `test`                     | aggregates `test node 22` and `test node 24` (vitest on each)                     |
| `data`                     | ruff lint + format, pytest, then regenerates the database and fails if it differs |
| `secret scan`              | gitleaks over the full branch history, plus a PII scan inside the workbook        |

The workbook is a zip of XML, and gitleaks skips it by extension before any
repo config applies — so the one binary in this repo was the one file no
scanner read. `scripts/scan_workbook_pii.py` unzips it and checks the parts a
spreadsheet hides: comment authors and signed-off comment bodies, document
properties, and every hostname against an allowlist of exact names. A new host
fails the job until someone adds it, which is the point.

`npm audit` runs after every other check in the build job on purpose: a new
advisory appearing overnight shouldn't abort before typecheck and lint have said
anything, and the artifact upload after it is `if: always()`, so the built
extension is still there when it fails.

## A note on the codes

These are negotiated corporate rates that belong to the companies that
negotiated them. Most are widely circulated, but a rate you aren't entitled to
can be refused at the counter or on check-in, sometimes after the reservation
looks confirmed — some vendors ask for a corporate ID or badge. Treat what this
tool finds as a shortlist to verify, not a booked price. Nothing here
circumvents a vendor's authentication or eligibility checks; it just fills in
codes you already have on their own public search forms.
